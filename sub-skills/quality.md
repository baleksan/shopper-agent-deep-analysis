You are performing search quality assessment for a single session log stream.

Your goals:
1) Evaluate how accurately each search result set matches the user query intent.
2) Evaluate the quality of follow-up query suggestions generated by the system.

Use the logs/query results to identify:
- user query text
- returned product/result signals (titles, categories, attributes, snippets, ids, metadata)
- follow-up suggestion candidates
- any indicators of relevance, refinement behavior, and result quality

Scoring requirements:
- For each result set, assign an ESCI-style relevance score per top results where possible:
  - E = Exact
  - S = Substitute
  - C = Complement
  - I = Irrelevant
- Produce an aggregate quality score (0-100) for:
  - query-to-results accuracy
  - follow-up suggestion quality
  - overall search quality
- Compute NDCG for each collection of search results:
  - estimate graded relevance from available signals using ESCI mapping
  - report NDCG@k (prefer k=5 and k=10 when possible)
  - if exact computation is not possible from logs, provide best-effort estimate and clearly state assumptions

Return your output in this structure:

1) Executive Summary
- 3-8 bullets of key quality findings.

2) Query vs Results Accuracy
- For each query/session block:
  - query text
  - relevance observations
  - ESCI distribution (counts or percentages)
  - query accuracy score (0-100)

3) Follow-up Suggestion Quality
- For each follow-up suggestion set:
  - suggestion list
  - relevance/coherence assessment vs original query and context
  - suggestion quality score (0-100)
  - issues (off-topic, repetitive, too broad, too narrow, missing key intents)

4) Ranking Quality Metrics
- NDCG calculations/estimates per result collection:
  - NDCG@5
  - NDCG@10
  - assumptions used

5) Outliers
- High performers:
  - list top query/result sets with strongest quality and why
- Low performers:
  - list weakest query/result sets with root causes

6) Recommendations
- Immediate fixes
- Short-term ranking/suggestion improvements
- Monitoring metrics and thresholds for ongoing quality tracking

Rules:
- Be explicit about assumptions and uncertainty.
- Prefer evidence-backed judgments using concrete snippets from logs.
- If required fields are missing, still produce a best-effort quality report and call out data gaps.
